# 設計書：KeySpeaker（USB Speaker & BLE Keyboard）

作成日: 2026年10月29日　状態: 設計案。USBスピーカー（S0、S1）は、Macの実機で確認済み（12章の「進み具合」）。そのほかは実機で未確認。

## 1. 目的と製品像

M5Stack Cardputer ADVを、気軽にカバンに入れて持ち歩ける「外付けスピーカー＆キーボード」にする。

製品名は **KeySpeaker**。説明として、目立つところに **「USB Speaker & BLE Keyboard」** を添える（2026-10-30決定）。画面、USBの機器名、ファイル名などには短い「KeySpeaker」を使う。PCの出力先の一覧に出る名前（いまは仮の名前）は、S2で「KeySpeaker」にする。

- **USBでつなぐと**：外付けスピーカー＆キーボード（ケーブル1本、相手の機器にはソフトもドライバーも入れない）
- **ケーブルを抜くと**：Bluetooth LEキーボード
- **導入**：Launcherから本体アプリだけの `.ino.bin` を入れるだけ

想定する使い方:

- スピーカーのないPC（デスクトップPC、Mac mini、モニターなど）につなぐ
- USB-Cから音声を出せる機器（スマホ、タブレット、デジタルオーディオプレーヤー、ゲーム機）につなぐ
- ケーブルを抜いて、Bluetooth（BLE）キーボードとして使う（Mac、iPhone・iPadなど。ゲーム機やテレビは、使えたらおまけ）
- Cardputerのイヤホン端子にイヤホンを挿し、「USB-Cイヤホンアダプター」として使う（6章）

優先順位は、つないだらすぐ使えること、音切れの少なさ、長時間の安定、聞き取りやすさ、音量とミュートの操作。デザインより基本機能と安定性を優先する。

### 1.1 設計の考え方

- **1つのアプリに1つの仕事。** モードを増やすと、使う人が「今どのモードか」を意識しなければならなくなる。ネットラジオはRADIO DAYS、ジョグダイヤルはMedia Jogに任せ、切り替えはLauncherで行う。
- **設定をさせない。** 起動したら何も選ばずに使える。USBとBLEの切り替えも自動にする。
- RADIO DAYS SDRの追加機能ではなく、独立した新規プロジェクトとする。既存のリポジトリは変更しない。

## 2. 対象範囲

| 区分 | 対象 |
|---|---|
| **基本の対象** | macOS、WindowsとのUSB接続（スピーカー＋キーボード）、BLEキーボード |
| **確認しながら広げる対象** | iPhone 15以降・USB-CのiPad、Android、USB音声出力のあるデジタルオーディオプレーヤー、ゲーム機。BLEキーボードとしてのゲーム機やテレビ |
| **対象外** | ChromeOS、ワイヤレス音声、ネットラジオ、3.5mm端子からのアナログ入力、PC側の送信アプリ |

## 4. 調査で分かったこと

### 4.1 USBスピーカーは普段の開発環境のまま作れる

- m5stack:esp32 3.3.10コア（RADIO DAYS SDRと同じ）に `USBAudioCard` クラスが入っている（手元のファイルで確認）。
  2026年4月に本家arduino-esp32へ追加された機能（[issue #12053](https://github.com/espressif/arduino-esp32/issues/12053)、[PR #12466](https://github.com/espressif/arduino-esp32/pull/12466)）。
- ESP32-S3ではUAC1、48kHz、16bit。UAC1はmacOS、Windows、iOS／iPadOS、Androidの多くで標準ドライバーで動く。
- PRの作者はWindows 11、Ubuntu、Macで動作確認したと報告している。
- 同じコアのUSB HID（キーボード、メディアキー）と組み合わせられる。
- ESP-IDF用のEspressif製UAC部品は「MacとWindowsのどちらか一方にしか対応できない」と公式資料にある（[公式資料](https://docs.espressif.com/projects/esp-iot-solution/en/latest/usb/usb_device/usb_device_uac.html)）。この点でもArduino側が目的に合う。
- 注意：`USBAudioCard` は新しく、PRのレビューでは複合デバイス周りの指摘もあった。
- 実機で見つかった不具合と回避策（2026-10-30、S1-4〜S1-6）:
  - コアのUSBイベント処理のタスクは、スタックが2KBしかない。そこでログを書き出すと、あふれて再起動する。イベントは書き留めるだけにして、`loop()` で書き出す。
  - PCが一時停止のあと再生を再開すると、TinyUSB（0.20.1）が、開いたままの音声の受け取り口（ISO OUTエンドポイント）を閉じようとして終わらずに固まり、ウォッチドッグで再起動する。`firmware/build.sh` のリンカー設定（`-Wl,--wrap=dcd_edpt_iso_activate`）で `UsbIsoFix.h` を前に挟み、設定が同じなら閉じずにそのまま使う。

### 4.2 「定期的な音切れ」の原因

- `USBAudioCard` のスピーカーはadaptive方式で、フィードバックエンドポイントがない。
- 相手の機器とCardputerのクロック差（±100ppm程度）がバッファーに少しずつたまり、周期的に溢れるか枯れる。48kHzでは1時間あたり約1.7万サンプル（約0.36秒）ずれる計算になる。
- atomic14の「スピーカーだけ音が割れる」という報告（[記事](https://blog.atomic14.com/2025/09/26/esp32-s3-usb-uac.html)）も、この型の問題と一致する。
- ESP32-S3には出力クロックを微調整できるAPLLがない。そのため本体側で、バッファー残量を見て再生速度をごくわずかに伸縮させる（簡易的な非同期サンプルレート変換）。これを最重要の安定化策とする。
- 実測（2026-10-30、Mac）：PCのほうがCardputerより約10〜17ppm遅く、補正なし（S0-6）では1.39時間ごとに音切れした（6時間で3回）。S1の補正（最大±200ppm、バッファー残量による比例制御、4点Hermite補間、`RateAdjust.h`）では、3時間鳴らして音切れ0回、補正量は約−16ppmで安定した。

### 4.3 ワイヤレス音声を対象外にした理由

- ESP32-S3はBLE専用で、Classic BluetoothもLE Audioも非対応。Bluetoothスピーカー（A2DP）にはなれない（[ESP-ADF公式](https://docs.espressif.com/projects/esp-adf/en/latest/solution-center/bluetooth-audio.html)）。
- Cardputer ADV（ESP32-S3FN8）にはPSRAMがない（[仕様](https://docs.m5stack.com/en/core/Cardputer-Adv)）。公開されているESP32のAirPlay受信実装は、どれもPSRAMが必須（[airplay-esp32](https://github.com/rbouteiller/airplay-esp32)、[squeezelite-esp32](https://github.com/sle118/squeezelite-esp32)）。
- WindowsなどにはPCの音を一般的なWi‑Fiスピーカーへ送る標準の仕組みがない。Wi‑Fiで音を送るには相手の機器に送信アプリが必要で、「`.ino.bin` を入れるだけで使える」という前提に反する。

### 4.4 3.5mm端子は出力専用

Cardputer ADVのイヤホン端子は出力専用で、音声を入力する機能はない。挿すと内蔵スピーカーのアンプが止まる（[M5Stack公式](https://docs.m5stack.com/en/core/Cardputer-Adv)）。音声はUSB-Cから受け取る。

### 4.5 BLEキーボードとしての対応

BLE（Bluetooth Low Energy）のHIDキーボードは、macOS、Windows、iOS／iPadOS、Androidが標準で受け付ける。Media Jogで、BLEキーボードとしてキーを送る実装はすでに動いている。ゲーム機やテレビなどは、BluetoothキーボードをBLE方式でも受け付けるかが機器ごとに違い、資料だけでは分からない。そのため、目標は「BLEキーボードとして使えること」とし、まずMacで確かめる（S5）。ほかの機器はS6で、手に入るものから試す（2026-10-30に決定）。

### 4.6 先人の実装

- 「Vibe Cardputer」は検索では見つからなかった（URLがあれば確認する）。
- Cardputer ADVのスピーカーとキーボードを同時に使う例、USBとBLEの両方に対応した例も見つからなかった。この組み合わせは新規の挑戦になる。

## 5. システム構成

```
┌──────────────── Cardputer ADV（1つのファーム）────────────────┐
│ キーボード(TCA8418) → キーマップ/Fnレイヤー → HIDレポート生成    │
│                                   ├→ USB HID   (USBモード)      │
│                                   └→ BLE HID   (BLEモード)      │
│ USB UAC1 48kHz ステレオ                                          │
│     → L+R合成 → 速度微調整 → リングバッファー → ES8311           │
│                                  → 内蔵スピーカー / イヤホン端子 │
│ 接続監視: USB SOFカウンター → モード自動切替                     │
│ 画面: 接続/音量/ミュート/バッファー/電池/警告                     │
└────────────────────────────────────────────────────────────────┘
```

### 5.1 USBモード

- 複合デバイス：UAC1スピーカー、HID（キーボード、Consumer Control）、開発中だけ使うデバッグ用CDC。
- エンドポイント数はESP32-S3の上限内に収まる見込み。
- 音量：データ表示とゲーム画面のモードで、本体の `[` / `]` / `\` からHIDの音量キーを相手の機器へ送る（8.3）。相手が音量を変えると、UACのFeature Unit経由で本体に値が届き、画面に表示する。音量は相手の機器の値を正としてひとつにそろえる。

### 5.2 BLEモード

- BLE HIDキーボード。Media JogのNimBLE実装（HIDサービス、ペアリング保存、切替時に押しっぱなしのキーを解放する処理）を移植する。
- 音声は扱わない。Wi‑Fiも使わない（Wi‑FiはLauncherでのインストールにだけ使う）。
- 接続先の切り替え（チャンネル1〜3）：ロジクールのEasy-Switchのように、Mac、iPad、スマホなど最大3台とのペアリングを覚えておき、つなぐ相手を切り替える。チャンネルごとにBLEのアドレスを変え、相手の機器からは別々のキーボードに見えるようにする。接続画面（`Fn+B`）で選び、キーボードモードの画面にチャンネル番号を出す（2026-10-30に追加。実機では未確認）。

### 5.3 モードの切り替え

- 自動：USBのSOF（ホストが1ミリ秒ごとに送る信号）があればUSBモード、なければBLEモード。
  - Cardputer ADVはケーブルの抜き差しを電源電圧から検知できないため、RADIO DAYS SDRの `usbLinkService()` で実証済みのSOF監視を使う。
  - 充電器だけをつないだ場合もBLEモードになる。
- 手動：`Fn+B` で切り替える（Media Jogと同じキー。予備の操作）。
- USBモードの間はBLEを止める。相手の機器にキーボードが二重に見えるのを防ぐ。
- USBの構成は起動時に決まり、動作中に変えられない。全機能を常に載せておく設計にする。

## 6. イヤホンアダプターとしての使い方

USBスピーカーとして動いている間に、Cardputerのイヤホン端子へイヤホンを挿すと、内蔵スピーカーが止まり、イヤホンから音が出るはず。イヤホン端子のないスマホやPC用の「USB-Cイヤホンアダプター」として使える。

- 追加のコードはほとんどいらない見込み。ES8311の出力はもともとイヤホン端子にもつながっている。
- ES8311はモノラルのため、両耳から同じ音が出る。
- イヤホンが挿さっているかをソフトで検知できるか（画面表示や音量の上限を切り替えるため）は未確認。
- 音量が大きすぎないか、雑音がないかをS0で確かめる。

## 7. 給電の考え方

この章は、USBケーブルでつなぐ場合（スピーカー＋キーボード）の話。BLEキーボードとして使うときはケーブルがいらず、Cardputer本体の電池で動くので、相手の機器の給電は関係ない（携帯ゲーム機もドックなしでよい）。

- **USBでつなぐなら、本命は電源につながった機器。** デスクトップPC、Mac mini、電源につないだノートPC、据え置きのゲーム機、ドックに挿した携帯ゲーム機なら、つなぐだけで使え、Cardputerも充電される。
- **スマホやタブレット**はUSB-C端子が1つのため、Cardputerをつなぐとその機器自体は充電できない。
  - 給電パススルー（USB PD）対応のUSB-Cハブを使えば、充電しながら使える（充電器 → ハブ → スマホ、Cardputerはハブのデータ用ポート）。
  - 短時間ならそのまま使ってよい。スマホの電池からCardputerに給電される。
- Cardputer側の充電をソフトで止められるか（スマホへの負担を減らすため）は、充電回路の作り次第で未確認。S0で調べる。
- Cardputerの電源スイッチがOFFだと動かず、充電もされない（M5Stack公式の注意書き）。

## 8. キーボード

TCA8418、4×14＝56キー。キーの押下と解放はイベントFIFOから読む。長文入力より、検索欄、ゲーム機やテレビの文字入力、短いメッセージなど「ちょっとした入力」に向く。

### 8.1 そのまま送るキー

通常の文字、Shift、Ctrl、Tab、Enter、Del（Backspace）。

### 8.2 修飾キーのOSプロファイル（本体で選択し、保存する）

| 本体のキー | Macプロファイル | Windowsプロファイル |
|---|---|---|
| `opt` | Option | Win |
| `alt` | Command | Alt |

### 8.3 モードとキーの割り当て（2026-10-30に決定、S2で実装）

`Fn+M` を押すたびに、**データ表示 → ゲーム画面 → キーボード** の順にモードが変わる。キーをPCへ送るのはキーボードモードのときだけ。ほかの2つのモードでは、キーは本体の操作と音の操作に使う。画面を見れば、いまどちらの使い方かが分かる。最後に使ったモードを覚えておき、次の起動はそのモードで始める。

USBがつながっていないとき（BLEキーボードとして使うとき）は、自動でキーボードモードだけになる。音が来ないので、データ表示とゲーム画面には切り替えず、`Fn+M` を押してもモードは変わらない。USBをつなぐと、3つのモードを切り替えられるようになる。

**どのモードでも**

| キー | 機能 |
|---|---|
| `Fn+M` | モードを切り替える（USBがつながっていないときは何もしない） |
| `Fn+B` | 接続画面を開く／閉じる（S5。BLEのチャンネル1〜3を選ぶ） |

**データ表示モード／ゲーム画面モード**（スピーカーとして使うとき）

| キー | 機能 |
|---|---|
| `[` / `]` / `\` | PCの音量− / 音量＋ / ミュート（HIDのメディアキー） |
| `Space` | 再生 / 一時停止 |
| `,` / `/` | 前の曲 / 次の曲（キーの印字の ← → と同じ向き） |
| `-` / `=` | 持ち上げ量を下げる／上げる（S0から。のちに整理する） |
| `b` | 低音カットのオン／オフ（S0から） |
| `r` | 回数のカウンターをリセット（S0から） |
| `v` | データ表示とゲーム画面を行き来する（S0との互換。`Fn+M` と同じ働き） |

**キーボードモード**（すべてのキーを普通のキーとしてPCへ送る。音量の操作はできない）

| キー | 機能 |
|---|---|
| 文字、Shift、Ctrl、Tab、Enter、Del | そのまま送る（DelはBackspace） |
| `opt` / `alt` | OSプロファイルに従う（8.2） |
| `Fn+; , . /` | ↑ ← ↓ →（キーの印字どおり） |
| `Fn+Shift+矢印` | PgUp / Home / PgDn / End |
| `` Fn+` `` | Esc |
| `Fn+1`…`Fn+=` | F1〜F12 |
| `Fn+Del` | 前方削除 |
| `Fn+[` / `Fn+]` | 英数 / かな（HIDのLANG2 / LANG1。Macのキーボードの英数・かなと同じ左右の並び。Windowsで効くかは要確認） |
| `Fn+O` | OSプロファイルの切り替え（Mac / Win、保存する） |

画面：左に、ゆっくり回る地球を描く（ゲーム画面の「地球防衛軍」とつながるように。2026-10-30に、かりポムの顔から変更）。地球は、グライコや地形と同じ長方形のブロック（6×3px、横8px・縦4px間隔）を、横16列×縦32段に並べて描く（約128px角）。海は青、陸は緑、極地は白で、縁に向かって暗くする。陸地の形は、見本と同じオリジナルの粗い地図（10度刻み）から作る。ブロックの粗さに合った、地形やグライコと揃った見た目にするため（2026-10-30、利用者の判断）。本物の地球と同じく、陸地が左から右へ流れる向きに、1分で1周くらいのゆっくりした速さで回す。各ブロックが地球のどの緯度・経度に当たるかは最初に一度だけ計算し、回すときは経度をずらして表を引くだけにする（描画を軽くするため）。背景はゲーム画面と同じ星空にする（黒い空に、白を中心に黄色とピンクの星。同じ色と割合を使い、白い星はときどきまたたく。地球の後ろには描かない）。BLEでペアリングを待っている間は、地球を灰色にする（陸地はうっすら残す）。つながると色が付く。右に `KEY` `BOARD`、接続（`USB` か `BLE CH1`〜`3`）とOSプロファイル、小さく `Fn+M MODE`（BLEのときは `Fn+B CH`）を出す。キーを打つたびに光らせるような動きは付けない（くどくなるため）。ゲーム画面がにぎやかなぶん、キーボードモードは静かな画面にする。

### 8.4 日本語環境での注意

- キーの印字はUS配列。相手の機器でこのキーボードを「US（ANSI）配列」に設定してもらう必要がある。
- 英数／かなの切り替えは `Fn+[` / `Fn+]`（8.3）。

## 9. 音声処理

- 相手の機器からは48kHzステレオで受け取り、本体でL+Rを合成してモノラルにする（音割れしないよう余裕を持たせる）。S0ではモノラルとして名乗る方式とも比較する。
- 機器によっては44.1kHzのまま出したがる（一部のオーディオプレーヤーなど）。必要なら44.1kHzにも対応させる。
- 1Wの小型スピーカーを守り、声を聞き取りやすくするため、低音カット（150Hz）、持ち上げ、リミッターを入れる（イヤホン使用時は切る）。S0-2で実装し、実機で確認した：本体の出力レベルは等倍のままにして、持ち上げ+9dB（+12dBまで良好）、低音カットはオンを初期値とする。低音カットの有無は聞き分けにくかったが、持ち上げたときのリミッターの余裕のためにオンにする。`-` `=` `b` の聴き比べ用キーは、のちの段階で整理する。
- 音の調整（S1のあと）：声を聞き取りやすくする2〜4kHzの持ち上げ、低音の倍音を足して低音があるように感じさせる仮想低音、詰まりや揺れの少ないリミッターへの改良。それぞれ実機で聴き比べて決める。
- 出力はまずRADIO DAYS SDRで実績のある `M5.Speaker` で始め、足りなければI2Sを直接制御する方式に移る。
- 速度微調整：バッファー残量の目標値を決め、ずれに応じて再生速度を±数百ppmの範囲で連続的に変える（線形補間）。

## 10. 開発環境と既存コード

- Arduino、m5stack:esp32 3.3.10、arduino-cliのビルドスクリプト（RADIO DAYS SDR、Media Jogと同じ構成）。
- ボード設定：USB Mode = USB-OTG（TinyUSB）、Flash 8MB、Partition `default_8MB`。
- 予備案：`USBAudioCard` に不具合があっても、コアに組み込まれたTinyUSBで音声機能（`CONFIG_TINYUSB_AUDIO_ENABLED`）はすでに有効。ESP-IDFへ移行せずに、自前のUACクラスをスケッチ内に持てる。
- 流用するもの（コピーして使い、元のリポジトリは変更しない）：
  - RADIO DAYS SDR：`RadioDays_Playout.h` の考え方（再バッファーと破棄の判断）、SOF監視、画面描画とキーボード周りの知見
  - Cardputer ADV Media Jog：NimBLE HID、HIDレポートの構成、押しっぱなしのキーを解放する仕組み、NVS（設定の保存）

## 11. Launcherとの互換性

維持できる見込み。

- 本体アプリだけの `.ino.bin` をLauncherのWi‑Fiアップロードで入れる（既存の2プロジェクトと同じ）。
- 「Launcherから起動するとHardware CDCは認識されず、TinyUSBなら動く」というRADIO DAYS SDRの知見が当てはまる。UACとHIDのためにTinyUSBは必須なので問題ない。
- サイズ：Media Jog（BLE）が0.90MB。Wi‑Fiを使わないので、それにUSB音声を足しても余裕を持って収まる見込み。S0で確認する。

## 13. 主なリスク

1. `USBAudioCard` がCardputer ADV上で実際にどれだけ安定するか（S0で確認）。ここが成り立たないと全体が成り立たないため、最初に検証する。→ Macでは、時計のずれの補正と、見つかった2つの不具合の回避（4.1）で安定した。Windowsはこれから。
2. スマホやタブレットからの給電で、接続を拒まれたり、電池の減りが大きすぎたりしないか（S0、S6で確認）。
3. BLE方式のキーボードが各機器で使えるか（MacはS5、ほかの機器はS6で確認）。
