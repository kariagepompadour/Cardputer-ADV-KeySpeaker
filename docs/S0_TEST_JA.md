# S0 検証手順：USBスピーカーだけの試作機

対象: `firmware/KeySpeaker_S0/KeySpeaker_S0.ino.bin`（`S2-5`。S0-6に、時計のずれの補正（S1-1）、ひとりでに再起動したときの原因の記録（S1-2、S1-3）と、その原因の修正（S1-4〜S1-6）、起動画面（S1-7〜S1-11）、USBキーボードと3つのモード（S2-1〜S2-5）を入れた版です。計測画面の右上に `S2-5` と出ます。S2の確かめ方は5.10です）S0-6までの検証結果は、この文書にそのまま残しています。S1の確かめ方は5.8です）
状態: 音量は実機で確認済み（Mac、2026-10-29）。S0-1より大きく聞き取りやすくなり、持ち上げは+9〜+12dBが良好、低音カットの違いは聞き分けにくい、という結果でした。初期値は+9dB・低音カットオンのままとします。時計のずれは、S0-3のバッファー推移方式で `drift +28 ppm`（`played` 6:38、underrun 0、overrun 0、Mac、2026-10-30）でした。測った時間が短いため、誤差は±15ppmほどあります。6時間の連続再生（S0-6、Mac、2026-10-30）では、鳴っていた時間6.02時間で音切れ3回、音飛び0回でした。音切れは1.39時間おきに規則正しく起き、どれもバッファーがゆっくり減って空になったときでした。PCのほうが約10〜17ppm遅いためです。描画の最長は17.2msで、メモリーの空きも一定でした。そのほかの項目は未確認です。

## 1. この試作機でわかること

- MacとWindowsが、Cardputer ADVをUSBスピーカーとして認識するか
- 音がきちんと出るか、PC側の音量とミュートが効くか
- 長時間鳴らしたとき、PCとCardputerの時計のずれで、バッファーがどう増減するか（設計書4.2）
- イヤホン端子、抜き差し、電源スイッチの動き

S0では、時計のずれを**わざと補正していません**でした。ずれの大きさを測るのが目的でした。S1-1から補正が入り、長時間鳴らしても音切れ（underrun）や音飛び（overrun）が起きないはずです。

キーボードはまだPCに文字を送りません。BluetoothとWi‑Fiも使いません。

## 2. インストール

1. `KeySpeaker_S0.ino.bin` を、`SHA256SUMS.txt` と照らし合わせて確認します。
2. いつもどおりLauncherのWi‑Fiアップロードで入れ、Launcherから起動します。
3. まず起動画面（スピーカーの網目に、かりポムのエンブレム）が2秒出ます。キーを押すとすぐ次へ進みます。その間もUSBと音の準備は進んでいます。
4. 画面に「KeySpeaker S0」と表示されます。

## 3. 画面の見方

| 行 | 意味 |
|---|---|
| `USB STREAMING` / `MOUNTED (no stream)` / `NOT CONNECTED` | 音声が届いている／接続はあるが音声は来ていない／未接続 |
| `SOF+` / `SOF-` | PCからの1ミリ秒ごとの信号が届いているか |
| 緑のバー、`buffer ... ms` | たまっている音声の量（0〜500ms）。縦線が再生開始の目安（100ms） |
| `underrun` / `overrun` | 音切れ（バッファーが空になった）／音飛び（バッファーが溢れた）の回数 |
| `adj ... ppm  trend ...  (m:ss)` | S1-1から。`adj` は、いま補正している量（＋はPCのほうが速いので、少し速く再生している）。しばらく鳴らすと、PCとCardputerの時計のずれと同じ値に落ち着きます。`trend` は、補正しきれずに残ったバッファーの増減で、補正が効いていれば0に近くなります。かっこの中は鳴っていた時間の合計で、1分を超えると `trend` が出ます（S0-6までは、ここが `drift ... ppm (m:ss played)` で、補正なしのずれそのものでした） |
| `since h:mm:ss` | 今回の再生が始まってからの時間 |
| `PC vol ... dB` | PC側の音量（0dBが最大、-50dBが最小）とミュート |
| 下の2本のバー | 左：PCから届いた音の大きさ。右：スピーカーへ送る音の大きさ（リミッターが効くと黄色） |
| `+9dB cut` | 持ち上げ量と、低音カットの状態（`cut`＝オン、`full`＝オフ） |

本体のキー:

| キー | 動作 |
|---|---|
| `-` / `=` | 持ち上げ量を下げる／上げる（0〜+18dB、3dBずつ。最初は+9dB） |
| `b` | 低音カットのオン／オフ（聴き比べ用） |
| `r` | 回数のカウンターをリセット |
| `v` | 計測画面と飛行ビジュアライザーの切り替え（最初は計測画面）。エンブレムの画面が出ているときは、計測画面に戻る |
| そのほかのキー（文字、`Enter`、`Space` など） | エンブレムの画面（起動画面と同じ）を2秒出す。もう一度押すと2秒を数え直す。`-` `=` `b` `r` は働いて画面を閉じる（S1-8） |

### S0-2で音量の仕組みを変えました

S0-1では、本体の出力レベル192の時点で信号がすでにほぼ最大になっていて、上げても割れるだけでした。S0-2では、小型スピーカー製品がよく使う次の処理を入れています。

1. **低音カット（150Hz以下）**：1Wのスピーカーでは鳴らない低音を取り除き、その分の余裕を音量に回します。
2. **持ち上げ**：全体を+9dB（約2.8倍）持ち上げます。
3. **リミッター**：大きな音の頭だけを瞬時に抑え、割れないようにします。

PC上の試験では、出力は上限を一度も超えず、小さな音は+9dB大きくなり、50Hzの低音は約19dB下がりました。

## 4. ログの取り方（あると助かります）

1秒ごとに次のような行がUSBシリアルに出ます。

```
[S0] t=125 stream=1 sof=1 fill=103 ms min=98 max=109 under=0 over=0 drop=0 rx_ppm=+41.2 spk_ppm=-2.0 vol=-12 mute=0 boost=9 cut=1 lim=-3.2 dB heap=...
```

**Mac**：ターミナルで、まずポート名を調べます。

```bash
ls /dev/cu.usbmodem*
```

次に、見つかった名前で記録を始めます（`XXXX` を置き換えてください）。止めるときは Ctrl+C です。

```bash
cat /dev/cu.usbmodemXXXX | tee ~/Desktop/keyspeaker_s0_mac.log
```

**Windows**：Arduino IDEのシリアルモニター（115200bps）で表示できます。必要な部分をコピーしてください。

ログが取れない場合は、画面の写真だけでも十分です。

## 5. 検証項目

### 5.1 認識と再生（Mac、Windowsそれぞれ）

1. USB-Cデータケーブルでつなぎます。
2. 出力デバイスとしてCardputerを選びます。名前は「M5STACK_CARDPUTER」「TinyUSB UAC1」など、まだ仮の名前で表示されるはずです。
   - Mac：システム設定 → サウンド → 出力
   - Windows：設定 → システム → サウンド → 出力
3. YouTube、ポッドキャスト、音楽などを再生し、音が出るか、雑音や音割れがないかを確かめます。
4. 画面が `USB STREAMING` になることを確かめます。

### 5.2 音量とミュート

1. PCの音量を上げ下げし、画面の `PC vol` が変わり、実際の音量も変わるか確かめます。
2. PCでミュートし、音が止まって `MUTE` と表示されるか確かめます。
3. PCの音量を最大にして、本体の `-` / `=` で持ち上げ量を変え、**聞き取りやすさと音の自然さのバランスが一番良い値**を探します。大きくしすぎると、音が詰まったように聞こえたり、息継ぎのように揺れたりします。
4. `b` で低音カットを切り替え、どちらが聞きやすいかを比べます。

### 5.3 1時間の連続再生（一番大事な項目です）

1. ラジオやプレイリストなど、途切れずに続く音声を流します。
2. 再生が始まったら `r` でカウンターをリセットします。
3. 1時間そのまま鳴らします。可能なら4章のログを取ります。
4. 終わったら、画面の `underrun`、`overrun`、`drift`、`buffer` の値を記録します。`drift` は、`played` が5分以上あれば十分に信頼できます。最初の音切れや音飛びが何分ごろに起きたかも分かると助かります。

曲の間などで少し途切れてもかまいません。`drift` は鳴っていた区間だけで計算します。

予想: driftが+なら、バッファーが少しずつ増えて、やがて `overrun` になります。−なら減って、やがて `underrun` になります。±100ppm程度なら、早ければ十数分で起きます。

### 5.4 抜き差し

1. 再生中にケーブルを抜き、数秒後に挿し直します。
2. PCがもう一度Cardputerを認識し、出力先に選べば音が戻るかを確かめます（OSが自動で戻すかどうかも記録してください）。

### 5.5 イヤホン端子（新しいアイデアの確認）

> **耳を守るため、先にPCの音量を小さく、本体の出力レベルも `-` で下げてから**イヤホンを耳に入れてください。

1. 再生中にCardputerのイヤホン端子へイヤホンを挿します。
2. 本体スピーカーが止まり、イヤホンから音が出るか確かめます。
3. 音量、雑音、左右から同じ音が出ているかを記録します。

### 5.6 電源スイッチと充電

1. 電源スイッチがONのまま使い、画面が動き続けるか確かめます。
2. 余裕があれば、USB接続中に電源スイッチをOFFにしたらどうなるかも記録します（止まる、動き続ける、など）。

### 5.7 飛行ビジュアライザー（S0-3で追加、S0-4で敵、S0-6でグライコを追加）

`v` で切り替えます。音量の履歴が、LEDのレベルメーターのようなブロックの棒（下から青、緑、黄、橙、赤のグラデーション）の地形になって左へ流れ、その上を小さな戦闘機が飛びます。ときどき正面へ色の帯が流れるレーザービームを撃ち、弧を描いて落ちるボムは地形に当たると爆発し、地形をブロック3つ分けずります。機体、敵、ボム、爆発は、地形と同じくらいの大きなドット（3×3px）で描いています。曲のビート（急に大きくなった瞬間）で、小さな的が現れます。ピンクの目玉ウォーカーは画面の右寄りに、まわりから点が集まってくるようにして出現し、ほかは右端から飛んできます（はっきりしたビートが少ない曲でも、数秒に1体は出ます）。的は6種類のオリジナルのドット絵で、ピンクの目玉ウォーカー、速い円盤、ジグザグに動く赤いミュータント、点滅する機雷を残していく青いボマー、撃つと小さな3匹に分かれるトゲトゲのポッドと、その分身です。戦闘機は前に出て高さを合わせて撃ち、当たると色とりどりの火花が画面の端まで飛び散ります。的もときどき、戦闘機をねらってオレンジの弾を撃ち返してきます。戦闘機はたいてい上下によけますが、当たるとバリア（水色の点の囲み）が一瞬光るだけで、やられることはありません。スコアもありません。静かな曲では的は出ません。上の小さな文字は、接続状態、持ち上げ量、音切れ（`U`）と音飛び（`O`）の回数です。

1. 音楽を流して `v` を押し、地形が音の強弱に合わせて動くか、戦闘機がなめらかに飛ぶかを見ます。
   棒は、PCの音量を下げる前の音で動きます。高さは「その曲のここ数秒の平均」と比べた大きさなので、盛り上がりは山に、静かな部分は谷になります。PCの音量を変えても動きは変わりません。PCでミュートすると、地面だけになります。空は真っ黒で、白を中心に、黄色やピンクの星がゆっくり流れます。
   地形は1分ごと、または曲間の無音（1.5秒以上）のあと音楽が戻ったときに、次の3つのパターンを順に繰り返します。(1) 流れる音量の地形だけ、(2) 地形の手前で**水色のグライコ**（昔のコンポの蛍光表示管の色）が踊る、(3) 地形の手前で**かりポム色のグライコ**（かりポムのEQ Classicと同じく、低音から高音へ青・水色・緑・黄緑・黄・橙・赤・マゼンタと1本ずつ色が変わる）が踊る。グライコは地面から立ち上がり、次の切り替わりで地面に沈みます。その間も地形は後ろで流れ続けます。グライコは左が低音、右が高音の30本の棒で、高さは地形のおよそ半分まで、白いピークの点がゆっくり落ちます。
2. **音が途切れたり、プツッと鳴ったりしないか**を確かめます。特にグライコの間は周波数の計算（FFT）をしているので、ログの `draw_max` と、音切れ（`U`）・音飛び（`O`）を見てください。描画が重いと、ここに影響が出るおそれがあります。
3. 本体のキー（`-` `=` `b`）がこの画面でも効くかを確かめます。
4. 余裕があれば、この画面のまま1時間鳴らし、計測画面での結果と比べます（ログの `draw_max` が1コマの描画にかかった最長時間です）。

### 5.8 時計のずれの補正（S1-1で追加）

S1-1は、バッファーの残りが減ってきたら再生をほんの少し遅く、増えてきたらほんの少し速くして、バッファーを再生開始直後の量（約80ms）に保ちます。変える量は最大で±200ppm（音の高さで0.35セント）で、耳では分かりません。補正が0のときは、音はS0-6とまったく同じです。

Macの上のシミュレーションでは、6時間テストと同じ−17ppmのずれで、6時間鳴らして音切れも音飛びも0回、バッファーは65〜69msで一定でした。±150ppmまでのずれ、途中でずれが変わる場合も同じ結果です（±200ppmを超えるずれは補正しきれません）。

**実機の結果（S1-1、Mac、2026-10-30）:** 鳴っていた時間3.01時間で、音切れ0回、音飛び0回でした（補正なしのS0-6では1.39時間ごとに音切れ）。バッファーは最小59ms、平均70〜73msで、時間がたっても減りませんでした。補正量 `adj` は、1時間ごとの平均で−16.3、−18.3、−15.8ppm。補正しきれずに残った増減 `trend` は±1ppm以内でした。途中、止まっていた音がもう一度流れ始めたときに本体が2回ひとりでに再起動したため、一番長く続けて鳴った区間は1時間39分です（再起動については5.8.1）。

1. いつもどおり音楽を流し、計測画面で `r` を押してカウンターをリセットします。
2. 数分たつと、`adj` が−10〜−20ppmくらいに落ち着くはずです（6時間テストと同じPCの場合）。
3. そのまま3時間以上鳴らします（S0-6では1.4時間おきに音切れが起きていたので、3時間で2回以上起きないことを確かめられます）。4章の記録係を使えば、ログの `adj_ppm` で補正の量の推移も分かります。
4. `underrun 0`、`overrun 0` のままか、`buffer` が60〜80msあたりで落ち着いているか、音に揺れや雑音がないかを記録します。

### 5.8.1 ひとりでに再起動する件（S1-2〜S1-6）

S1-1の3時間テスト（Mac、2026-10-30）では、止まっていた音がもう一度流れ始めたときに、本体が2回ひとりでに再起動しました（14:47と15:05。S0-6のログにも、同じ形が何回かありました）。S1-2を入れた直後の最初の起動でも、1秒たたずに `PANIC` で再起動しました（2026-10-30 16:15）。S1-2とS1-3は、再起動の理由（`PANIC` ならプログラムの異常、`TASK_WDT` や `INT_WDT` なら処理が止まったまま、など）と、直前に各処理がどこまで進んでいたかを、再起動のあとにログと画面へ出します。S1-3は、異常で落ちたときに本体が自動で保存する記録（コアダンプ）も読み出し、落ちた処理の名前とプログラムの場所をログの `[CRASH]` の行に出します（画面には出ません。記録係でログを取ってください）。

**原因（S1-3の記録から）:** 落ちていたのは、USBのイベント（音の開始・停止、音量など）を処理するコアの作業でした。この作業はメモリー（スタック）が2KBしかないのに、本体のプログラムがそこでログの文字を書き出していたため、イベントが来たときにあふれていました。S0のころからあった問題です。S1-4では、そこではイベントを書き留めるだけにして、ログへの書き出しは別の場所で行うように直しました。

**S1-4の結果（Mac、2026-10-30 20:22〜20:30）:** 起動直後に落ちることはなくなりました。しかし、Macで一時停止して10秒後に再開すると、10回とも `TASK_WDT`（処理が止まったまま）で再起動しました。記録によると、再開の合図を受けたUSBの基本部分（TinyUSB）が、音の受け取り口を閉じ終わるのを待つところで止まっていました。「閉じ終わった」という知らせを、同じ部品の割り込み処理が先に消してしまうことがあり、待ちが終わらなくなります。

**S1-5:** その関数の前に、時間の上限つきで受け取り口を閉じる処理（`UsbIsoFix.h`）を挟みました。閉じ終わったことを、割り込み処理に消されない別の目印で確かめます。`firmware/build.sh` でビルドしたときだけ有効です。

**S1-5の結果（Mac、2026-10-30 20:41〜20:46）:** 8回とも再起動しました。挟んだ処理は呼ばれていましたが、3ミリ秒待っても受け取り口は閉じず、そのあと元の処理がやはり止まりました。受け取り口が、そもそも閉じられない状態になっているようです。

**S1-6:** 再開のとき、受け取り口がまだ開いていて設定（種類、大きさ）も前回と同じなら、閉じて開け直すのをやめ、そのまま使います。元の処理がしていたのは、閉じてから同じ設定を書き戻すことだけだからです。**S1-6の結果（Mac、2026-10-30 20:49〜20:54）:** 一時停止と再開を10回繰り返して、再起動は0回（`boot 1` のまま）でした。PCが音の送信を止めて再開した5回（短い一時停止では、Macは送信を止めないことがあります）は、すべて受け取り口をそのまま使い（`kept5`）、再開後も音は届き続け、音切れ・音飛びは0回でした。ログの行末の `iso=kept回数/passed回数` で、そのまま使った回数（kept）と、元の処理に任せた回数（passed）が分かります。

1. 計測画面の `since` の行に、`boot 1 POWERON` のように、起動した回数と最後の起動の理由が出ます。
2. 音楽を流し、PCの再生を一時停止して10秒ほど待ち、再開します。これを何回か繰り返します。
3. `boot` の数が増えたら再起動しています。そのときの `boot` の行（例: `boot 2 PANIC`）を写真で残してください。ログを取っていれば、`rst=`、`prev=` に詳しい記録が出ます。

### 5.10 USBキーボードと3つのモード（S2-1で追加）

**実機の結果（S2-1、Mac、2026-10-30）:** USBスピーカーとキーボードとして同時に認識された。計測画面の `[` `]` `\` で、Macの音量の上げ下げとミュートができた。キーボードモードで、Macに文字を入力できた。`Fn+;` `Fn+,` `Fn+.` `Fn+/` の矢印、`Fn+[` `Fn+]` の英数・かな、`alt+C` / `alt+V` のコピーと貼り付け、`` Fn+` `` のEsc（`alt+Space` で開いたSpotlightが閉じた）もできた。モードの記憶、一時停止と再開は未確認。

**S2-2〜S2-4（Mac、2026-10-30）:** キーボード画面に、キー（オレンジ）と意味（白）の早見表と、`USB` `Mac` の右に `A/あ`（最後に `Fn+[` / `Fn+]` で切り替えたほうがオレンジ）が出ることを確かめた。起動時に、Launcherで押したキーで案内が出る問題を直した。S2-5で、Macのサウンドの出力先の名前が「TinyUSB UAC1」から「KeySpeaker」に変わった（選び直さなくても、出力先はそのまま）。

S2-1から、CardputerはUSBスピーカーに加えて、USBキーボードとメディアキー（音量、再生）としても認識されます。`Fn+M` を押すたびに、**計測画面 → ゲーム画面（ビジュアライザー） → キーボード** とモードが変わります。キーがPCへ文字として送られるのは、キーボードモードのときだけです。最後に使ったモードは覚えていて、次の起動はそのモードで始まります。

**計測画面とゲーム画面のキー**

| キー | 動作 |
|---|---|
| `[` / `]` / `\` | PCの音量− / 音量＋ / ミュート |
| `Space` | 再生 / 一時停止 |
| `,` / `/` | 前の曲 / 次の曲 |
| `-` / `=`、`b`、`r` | 持ち上げ量、低音カット、カウンターのリセット（これまでどおり） |
| `v` | 計測画面とゲーム画面の切り替え |
| そのほかのキー | エンブレムの画面を2秒。下に `Fn+M  KEYBOARD` と出る |
| `Fn+M` | モードの切り替え |

**キーボードモードのキー**（すべてPCへ送る。音量の操作はできない）

| キー | 動作 |
|---|---|
| 文字、Shift、Ctrl、Tab、Enter、Del | そのまま（DelはBackspace） |
| `opt` / `alt` | Macのとき Option / Command、Windowsのとき Win / Alt |
| `Fn+;` `Fn+,` `Fn+.` `Fn+/` | ↑ ← ↓ → |
| `Fn+Shift+` 上の4つ | PgUp / Home / PgDn / End |
| `` Fn+` `` | Esc |
| `Fn+1` … `Fn+0` `Fn+-` `Fn+=` | F1 … F12 |
| `Fn+Del` | 前方削除（Delete） |
| `Fn+[` / `Fn+]` | 英数 / かな |
| `Fn+O` | Mac / Windows の切り替え（覚えておく） |
| `Fn+M` | モードの切り替え |

キーボードモードの画面は、いまは文字だけです（回る地球は次の版で入れます）。打った文字はログに出しません。

1. 入れて起動し、Macにつなぎます。初めてキーボードとして認識されるとき、Macが「キーボード設定アシスタント」を出すことがあります。そのときは、出てきた案内に従ってキーを押すか、閉じてください。種類を聞かれたら「ANSI（US）」を選びます。
2. 音楽を流し、音がこれまでどおり出るか確かめます（キーボードが加わっても、音が途切れないこと）。
3. 計測画面で `[` `]` `\` を押し、Macの音量が変わるか、ミュートできるか確かめます。`Space` で再生／一時停止、`,` `/` で前後の曲。
4. `E` などを押して、エンブレムの画面の下に `Fn+M  KEYBOARD` と出るか確かめます。
5. `Fn+M` を押して、ゲーム画面、キーボードへと切り替わるか確かめます。
6. キーボードモードで、メモ帳などに文字を打ちます。大文字（Shift）、記号、Enter、Del、矢印（`Fn+;` など）、`Fn+[` `Fn+]` の英数・かな、`alt+C` / `alt+V`（Macのコピーと貼り付け）を試します。
7. 電源を入れ直して、最後のモードで始まるか確かめます。
8. 余裕があれば、一時停止と再開（5.8.1）も何回か試し、再起動しないか確かめます。

### 5.9 余裕があれば

- iPhone・iPad（USB-C）やAndroidにつないで、音が出るか。
- Macの「Audio MIDI設定」で、このデバイスのフォーマットが「48,000Hz」になっているか。

## 6. 報告してほしいこと

- OSごとに：認識したか、表示された名前、音が出たか、音量とミュートが効いたか
- 1時間後の画面の値（写真で可）、またはログファイル
- 一番良かった持ち上げ量と、低音カットのオン／オフどちらが聞きやすかったか
- 抜き差し、イヤホン、電源スイッチの結果
- 気になった音（プツッという音、雑音、音の遅れなど）
